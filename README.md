# ระบบงานพัสดุ โรงเรียนกาวิละวิทยาลัย

เว็บแอปรุ่นต้นแบบสำหรับจัดซื้อและจัดจ้างยอดสุทธิไม่เกิน 5,000 บาท เจ้าหน้าที่ใช้งานผ่านฐานข้อมูลกลางเดียวกัน มีบัญชีผู้ดูแล/เจ้าหน้าที่ ตั้งค่าผู้ลงนาม เลขแยกประเภท/ปีงบประมาณ แก้ไขเลขโดยเก็บประวัติ และหน้าเอกสาร A4 สำหรับพิมพ์หรือบันทึก PDF

## เริ่มใช้งาน

ต้องใช้ Node.js 24 ขึ้นไป (ใช้ `node:sqlite` ซึ่ง Node ยังแสดงคำเตือน experimental) ไม่ต้องติดตั้งฐานข้อมูลแยก

```sh
cd /workspace/passadukwc
npm ci --cache /tmp/npm-cache
npm test
npm start
```

เปิดที่เครื่องที่รัน พอร์ต 3000 สร้างผู้ดูแลคนแรกที่ `/setup` จากนั้นล็อกอิน เข้าเมนูผู้ดูแล ตั้งชื่อโรงเรียน ผู้ลงนาม และเพิ่มเจ้าหน้าที่แต่ละคน ไม่สร้างบัญชีหรือรหัสผ่านเริ่มต้นให้โดยอัตโนมัติ ตั้ง `SETUP_TOKEN` ก่อนเปิดให้บุคคลอื่นเข้าถึงหน้าเริ่มต้น แม้ในโหมดพัฒนา

ใช้ `.env.example` เป็นตัวอย่างเท่านั้น แอปไม่อ่าน `.env` อัตโนมัติ ถ้าใช้ไฟล์นี้ให้เรียก `node --env-file=.env app.js` และเก็บไฟล์ไม่ให้ผู้อื่นอ่าน

## Vercel + Supabase PostgreSQL

เตรียม entry สำหรับ Vercel และฐานข้อมูล PostgreSQL แล้ว ดูขั้นตอนที่ [VERCEL.md](VERCEL.md) ต้องตั้ง `DATABASE_URL`, `SESSION_SECRET`, `SETUP_TOKEN` และสร้าง schema ก่อน deploy บน Vercel จะไม่ใช้ SQLite ไม่มีการเชื่อมบัญชีหรือ deployment จริงให้โดยอัตโนมัติ

## การใช้งานออนไลน์จริงบนเซิร์ฟเวอร์ SQLite

ติดตั้งแอป **หนึ่ง instance** บนเซิร์ฟเวอร์ที่มี persistent disk ทุกคนใช้ URL HTTPS เดียวกัน ไม่รันฐานข้อมูลแยกตามเครื่องเจ้าหน้าที่ ใช้ reverse proxy เช่น Caddy/Nginx จัดการ HTTPS และส่งต่อไปยังแอป ตั้ง `NODE_ENV=production`, `SESSION_SECRET` แบบสุ่มอย่างน้อย 32 ตัวอักษร, `SETUP_TOKEN` แบบสุ่มแยกต่างหาก และ `TRUST_PROXY=1` เฉพาะเมื่อมี reverse proxy ที่เชื่อถือได้ 1 ชั้นและไม่เปิดแอปให้เข้าถึงข้าม proxy โดยตรง การรัน production บน HTTP จะล็อกอินไม่ได้เพราะ cookie กำหนด secure

มี Dockerfile ให้ใช้ได้ ต้อง mount volume ถาวรที่ `/app/data` ซึ่งผู้ใช้ node (UID 1000) เขียนได้ และส่งค่าลับผ่านระบบ secrets ของโฮสติ้ง ไม่รวมค่าลับใน image ยังไม่ได้ทดสอบ Docker build หรือ deploy จริง และยังไม่มีโดเมน/HTTPS ที่ตั้งค่าให้

ถ้ารันโหมด SQLite ใช้ WAL และ transaction `BEGIN IMMEDIATE` จัดสรรเลขและบันทึกข้อมูลร่วมกัน มี unique constraint กันเลขซ้ำ แก้เลขย้อนหลังจะไม่ทำให้ counter ลดลง และเอกสารที่บันทึกแล้วเก็บชื่อผู้ลงนามเดิม ไม่รองรับฐานข้อมูลบน network filesystem หรือหลาย replicas ปีงบประมาณเริ่ม 1 ตุลาคมตามเวลาไทย ผู้ใช้เลือกปีได้เอง

## แบบเอกสารและข้อจำกัดก่อนใช้จริง

ชุดพิมพ์เป็น **แบบร่าง 5 หน้า**: รายงานขอซื้อ/จ้าง รายงานผลการพิจารณาและขออนุมัติ ใบสั่งซื้อ/จ้าง บันทึกตรวจรับ และบันทึกขอเบิกจ่าย โครงเนื้อหายังเป็นแบบทั่วไป ไม่ใช่เอกสารครบถ้วนรับรองตามกฎหมาย ไม่ได้สร้างใบเสนอราคา ใบเสร็จ หรือหลักฐานแทนผู้ขาย ต้องตรวจแบบเฉพาะแต่ละขั้นตอนกับเจ้าหน้าที่พัสดุและเอกสารโรงเรียน แล้วจึงพัฒนาต่อ รายละเอียดตรวจรับ/ส่งมอบในหน้าพิมพ์ยังเป็นช่องกรอกบนกระดาษ ไม่มีการบันทึกอนุมัติหรือลายเซ็นอิเล็กทรอนิกส์

นำไฟล์ตราครุฑ PNG ที่โรงเรียนรับรองและมีสิทธิ์ใช้งาน วางที่ `public/garuda.png` ระบบจะแสดงแทนช่องว่างโดยอัตโนมัติ ยังไม่ได้แนบตราจริงหรือฟอนต์ราชการ ต้องตรวจหน้าพิมพ์จริงบน A4 และติดตั้งฟอนต์ TH Sarabun New/Sarabun ในเครื่องผู้พิมพ์ก่อนยืนยันรูปแบบ

ขอบเขตวงเงินเป็นข้อกำหนดของแอป **ไม่ใช่การยืนยันข้อยกเว้น e-GP** และห้ามแบ่งซื้อแบ่งจ้างเพื่อหลีกเลี่ยงระเบียบ ต้องตรวจข้อกำหนดปัจจุบัน วิธีจัดซื้อ แหล่งเงิน และหนังสือเวียนที่ใช้กับโรงเรียนอีกครั้ง ก่อนใช้เอกสารจริง

พยายามเข้าถึง https://www.myschoolmis.com/SchoolMAM.html, https://www.cgd.go.th, https://www.gprocurement.go.th และ https://ratchakitcha.soc.go.th เมื่อ 18 ตุลาคม 2569 แต่ network proxy ตอบ 403 จึงยังไม่ได้อ่าน/ยืนยันเนื้อหาจากเว็บไซต์เหล่านี้ และไม่ได้คัดลอกแบบฟอร์มจากระบบที่ซื้อมา

## สำรองและคืนข้อมูล

```sh
npm run backup -- /secure/backups/school-2026-10-18.db
```

ใช้ SQLite backup API จึงสำรองขณะใช้งานได้ ตั้งงานสำรองประจำวันไปยังที่จัดเก็บแยก จำกัดสิทธิ์และเข้ารหัสตามนโยบายโรงเรียน ไฟล์ backup มีข้อมูลส่วนบุคคลและ session เมื่อคืนข้อมูลให้หยุดแอปก่อน แทนไฟล์ฐานข้อมูลด้วย backup ลบไฟล์ `-wal`/`-shm` เดิมเฉพาะเมื่อแอปหยุดและเก็บสำรองแล้ว ล้างตาราง `sessions` เพื่อตัด session เดิม และเริ่มแอปใหม่ ทดสอบคืนข้อมูลในระบบแยกก่อนใช้จริง

ประวัติแก้ไขเก็บก่อน/หลังในฐานข้อมูลและแสดงกิจกรรม 50 รายการล่าสุด หน้าค้นหาแสดงสูงสุด 200 รายการ ยังไม่มีแนบไฟล์ ยกเลิกรายการ export ประวัติ ระบบอนุมัติหลายขั้น หรือนำเข้าข้อมูลจากโปรแกรมเดิม ผู้ดูแลฐานข้อมูลยังแก้ audit ได้ จึงไม่ใช่ audit ที่ป้องกันการดัดแปลงระดับกฎหมาย

## ทดสอบ

`npm test` ทดสอบ HTTP จริงด้วย SQLite และ PostgreSQL ชั่วคราว (ใช้ embedded-postgres ซึ่งต้องรันด้วยผู้ใช้ปกติ ไม่ใช่ root): สร้าง admin/login, CSRF, สิทธิ์ staff, วงเงิน, บันทึกพร้อมกัน 8 รายการ, เลขซ้ำ, แยกซื้อ/จ้าง, optimistic concurrency, escape HTML, render เอกสาร, ผู้ลงนามเดิม และเพิกถอน session ไม่มีการทดสอบความถูกต้องทางกฎหมายหรือภาพพิมพ์จริงด้วย browser
